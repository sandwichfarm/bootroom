  <behavior>
    - `ws_handler` accepts `WebSocketUpgrade` and `State<Arc<AppState>>` and returns `impl IntoResponse` (a 101 upgrade response).
    - After upgrade, the handler splits the socket into sink + stream, spawns a writer task draining a `tokio::sync::mpsc::channel::<WsMessage>(32)`, sends `WsMessage::Hello { version: env!("CARGO_PKG_VERSION").to_string() }` as the first frame, then reads frames in a loop and dispatches to `handle_wire`.
    - `handle_wire` matches each `WsMessage` variant: SerialIn/SerialOut → `tracing::trace!`; Launch/Reset → `tracing::info!`; State/Hello from client → `tracing::warn!` (server-owned message kinds — client sending them is a protocol error but does not close the connection in Phase 2).
    - Malformed JSON (`serde_json::from_str` returns Err) produces `tracing::warn!(error = %e, payload = %text)` and continues the loop — no panic, no disconnect.
    - On Close frame or stream error, the reader loop breaks; the writer task drains the channel then exits when `tx` is dropped; the handler returns.
    - The route is reachable at `/ws` via `axum::routing::any` (per 02-RESEARCH.md Pattern 1 line 420: `any` instead of `get` — keeps the door open for future protocol negotiation without breaking the route, even though WS upgrades arrive as HTTP GET today).

    Create new file `crates/bootroom/src/ws.rs`. Implement EXACTLY per 02-RESEARCH.md Pattern 1 (code block at lines 313–411) with these specific choices:

    1. Public function `pub async fn ws_handler(ws: WebSocketUpgrade, State(state): State<Arc<AppState>>) -> impl IntoResponse`. Body: `ws.on_upgrade(move |socket| handle_socket(socket, state))`.

    2. Private async `handle_socket(socket: WebSocket, state: Arc<AppState>)`:
       - `let (mut sink, mut stream) = socket.split();` (requires `futures_util::{SinkExt, StreamExt}`).
       - `let (tx, mut rx) = tokio::sync::mpsc::channel::<WsMessage>(32);` (bounded at 32 per 02-RESEARCH.md Security Domain "WS frame flooding" mitigation).
       - Spawn writer task: while `rx.recv().await` returns `Some(msg)`: serialize with `serde_json::to_string(&msg)`; on Ok send `Message::Text(json.into())`; on Err log `tracing::error!` and continue. After the recv loop exits, best-effort `let _ = sink.close().await;`.
       - Send initial `Hello`: `let _ = tx.send(WsMessage::Hello { version: env!("CARGO_PKG_VERSION").to_string() }).await;`. The ignored result is intentional — if the channel is closed already, the handler will exit cleanly.
       - Reader loop: `while let Some(msg_res) = stream.next().await { ... }`. Match each frame:
         - `Ok(Message::Text(text))` → `serde_json::from_str::<WsMessage>(&text)`: on Ok call `handle_wire(wire, &tx, &state).await`; on Err `tracing::warn!(error = %e, payload = %text, "bad WsMessage")` and continue.
         - `Ok(Message::Binary(_))` → `tracing::warn!("unexpected binary WS frame; protocol is JSON")`. Do NOT close — log and continue.
         - `Ok(Message::Ping(_)) | Ok(Message::Pong(_))` → no-op (axum auto-handles pings).
         - `Ok(Message::Close(_))` → break.
         - `Err(e)` → `tracing::debug!(error = %e, "ws recv error; closing")`; break.
       - After the loop, `drop(tx); let _ = writer.await;` (drop the sender to close the writer task, then await its join — best-effort).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → `/ws` (loopback only) | WS frames arrive as text payloads parsed via `serde_json::from_str::<WsMessage>`. Strict tag matching rejects unknown variants. Server is loopback-bound by Phase 1 default. |
| `/ws` handler → mpsc channel → writer task | In-process; both ends are trusted code. The bounded channel (capacity 32) is the back-pressure point. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-14 | Spoofing | Cross-Site WebSocket Hijacking — a malicious page from another origin opens a WS to `/ws` (browsers do not enforce SOP on WS upgrades) | accept | Loopback bind (Phase 1 default `--host 127.0.0.1`) makes this require local foothold. axum's `WebSocketUpgrade` does NOT auto-check the `Origin` header; Phase 2 does not add an allow-list because the bind is loopback. If Phase 4+ ever binds non-loopback, an origin allow-list MUST be added. Out of Phase 2 scope per 02-RESEARCH.md Security Domain. |
| T-02-15 | Denial of Service | WS frame flooding causes the mpsc queue to grow unbounded | mitigate | Channel bounded at capacity 32 (`tokio::sync::mpsc::channel::<WsMessage>(32)`). When full, `send().await` back-pressures the producer (the reader loop), naturally throttling the upstream flow. Acceptable for a loopback dev tool. |
| T-02-16 | Denial of Service | Malformed JSON in a Text frame causes server panic | mitigate | `serde_json::from_str` returns Result; the handler matches on Err and logs `tracing::warn!`. No `.unwrap()` on parse, no panic. |
| T-02-17 | Tampering | Client sends `State` or `Hello` frames (server-owned message kinds) attempting to spoof authoritative status | mitigate | `handle_wire` logs `tracing::warn!("client sent server-owned message kind")` and ignores. Connection stays open (recoverable; protocol error but not fatal). |
| T-02-18 | Spoofing | Future router refactor strips COOP/COEP layers from the `/ws` upgrade response, silently downgrading cross-origin isolation for connected pages | mitigate | Regression test `ws_upgrade_response_carries_coop_coep` (task 2) asserts both headers appear on a non-upgrade GET to `/ws`. The test runs on every `cargo test` invocation. (Pitfall #4 mitigation.) |
| T-02-19 | Resource exhaustion | base64-encoded `SerialIn` payload could trigger excessive allocation if decoded | accept | Phase 2 server does NOT decode `SerialIn` (pass-through observer only — `data: _` in the match arm discards). When Phase 4 decodes for the headless run mode, it will cap input size at the scenario engine layer. |
| T-02-20 | Denial of Service | Slowloris-style attacker holds a WS connection open without sending frames | accept | axum's WS extractor auto-handles ping/pong heartbeats. A misbehaving client that never closes wastes one tokio task and one mpsc buffer (32 frames = ~few KB). Loopback dev tool; acceptable resource cost. Phase 5 may add per-connection idle timeout. |
| T-02-21 | Tampering | `Launch` / `Reset` frames remotely trigger page reload of a connected user | accept | Loopback bind + single-user dev tool means no remote attacker. Phase 2 logs only; does not broadcast to other connections (no other connections in scope). |
</threat_model>
