The enum shape is contractually fixed by 02-CONTEXT.md `<decisions>` and re-verified in 02-RESEARCH.md Pattern 2. Wire shapes the browser and server agree on:

- `{"type":"Hello","version":"<CARGO_PKG_VERSION>"}` — server greeting
- `{"type":"SerialIn","data":"<base64>"}` — host→guest bytes (server may forward in Phase 4)
- `{"type":"SerialOut","data":"<base64>"}` — guest→host bytes (browser emits, server logs)
- `{"type":"State","state":"Running"}` — server-authoritative status
- `{"type":"Launch"}` / `{"type":"Reset"}` — client emits before page reload

Public surface required by downstream plans 02 (WS handler) and Phase 4 (headless run):

```rust

    SerialOut { data: String },

    Reset,
    Hello     { version: String },
}
pub enum GuestState { Idle, Loading, Running, Halted }
```

Both enums MUST derive `Serialize, Deserialize, Debug, Clone, PartialEq, Eq`. `GuestState` additionally derives `Copy` (per 02-CONTEXT.md `<decisions>`).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| (none) | `bootroom-core` is a pure-types library with no I/O, no network, no filesystem. It exposes types other crates serialize/deserialize. There are no trust boundaries within this crate. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `WsMessage` deserialization of untrusted input | accept | Deserialization happens in the `/ws` handler (plan 02), not in this crate. This crate provides only the Serialize/Deserialize derives; serde with strict tag matching rejects malformed variants by returning `Err`, never panics. Future Phase 4 will cap input size on the consumer side. |
| T-02-02 | Denial of Service | Pathologically large `data: String` payload in `SerialIn`/`SerialOut` | accept | This crate cannot enforce size limits — it knows nothing about transport. The WS handler (plan 02) is bounded by axum's default frame size limit (16 MiB) and the per-connection mpsc capacity (32 frames). Cap added on the consumer side, not at the type definition. |
| T-02-03 | Information Disclosure | `WsMessage::Hello { version }` leaks the server's exact `CARGO_PKG_VERSION` | accept | bootroom is loopback-only per PROJECT.md; leaking the version to a same-host client is not a meaningful disclosure. Phase 6 may tighten if the binary is ever exposed beyond loopback. |
</threat_model>
