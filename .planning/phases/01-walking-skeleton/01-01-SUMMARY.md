## Decisions Made

### 1. Physical directory rename deferred

`PROJECT.md` calls for renaming `~/Develop/norn-web` to `~/Develop/bootroom`. We **did not** do the on-disk move because:

- Mid-session shell history, editor sessions, and the orchestrator's `cwd` all reference `norn-web`.
- The Cargo workspace, binary, and crates are all named `bootroom`; only the containing directory name differs from project identity.
- The user can run `mv ~/Develop/norn-web ~/Develop/bootroom` at any quiescent point; nothing in the workspace embeds the directory name.

Recorded in README under the "Note" callout so future plan 01-02 (qemu-wasm asset pipeline) and 01-04 (server) know to refer to paths via `$CARGO_MANIFEST_DIR`, not `~/Develop/bootroom`.

### 2. Workspace license inheritance over string duplication

The plan's verification step `grep -l "MIT OR Apache-2.0" crates/*/Cargo.toml | wc -l` was written expecting 2, but each crate uses `license.workspace = true` (per task body) which is the idiomatic 2024-edition pattern. Verified via `cargo metadata` that both crates resolve to `MIT OR Apache-2.0`. No deviation from intent; the grep-based assertion was a self-contradiction in the plan text.

### 3. `Cargo.lock` committed

`bootroom` is a binary, not a library — `Cargo.lock` is committed to guarantee reproducible CI builds. `.gitignore` explicitly does NOT list it.

### 4. Lints policy locked from day one

Every crate sets:

```toml
[lints.rust]
unsafe_code = "forbid"

[lints.clippy]
pedantic = { level = "warn", priority = -1 }
```

The `priority = -1` lets specific clippy lints raise/lower individually without losing the pedantic baseline. The library crate also adds a redundant `#![cfg_attr(not(test), deny(unsafe_code))]` at the crate root so the policy is doubly explicit (defence in depth against accidental `[lints]` removal).

### 5. `resolver = "3"`

Edition 2024 default; explicit so future contributors don't get the implicit-1 default if a `[package]` is ever moved out from under the workspace.
