Vendor xterm.js 5.3.0, its CSS, and xterm-pty 0.12.0 into `crates/bootroom/web/vendor/`. Purpose: Phase 1 plan 01-06 (the UI shell) imports these vendored files via plain script tags. Vendoring them first means the UI work is pure HTML/JS authoring with no fetching steps.

Output: Three vendored library files plus VERSIONS.md pin record plus LICENSES.md upstream-license capture.
</objective>

<interfaces>
The exact import surface plan 01-06 will use.

xterm.js 5.3.0 exposes the global `Terminal` constructor when loaded as a classic script. Plan 01-06 will use:
- `new Terminal()` constructor
- `term.open(element)` to mount
- `term.loadAddon(masterAddon)` to attach the xterm-pty bridge
- `term.attachCustomKeyEventHandler(() => false)` to no-op keyboard input in Phase 1

xterm-pty 0.12.0 exposes the global `openpty()` function returning `{ master, slave }`:
- `master` is an xterm.js addon
- `slave` is the PTY end exposed to qemu-wasm via `Module.pty = slave`

The two scripts MUST load in this order: xterm.js first (defines `Terminal`), then xterm-pty.js (depends on `Terminal`).
</interfaces>
