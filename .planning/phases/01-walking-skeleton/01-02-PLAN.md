    # bootroom Makefile
    # Only target right now is `qemu-assets`, which (re)builds the embedded
    # qemu-wasm artifacts from the qemu-wasm submodule via docker. Run this
    # whenever the qemu-wasm submodule pinned commit changes. Output is
    # committed to git so end users do NOT need docker.

    .PHONY: qemu-assets clean-qemu-assets

    QEMU_WASM_DIR := qemu-wasm
    QEMU_OUT_DIR  := crates/bootroom/assets/qemu

    qemu-assets:
    	@command -v docker >/dev/null || { echo "ERROR: docker is required to (re)build qemu-wasm artifacts" >&2; exit 1; }
    	@test -d $(QEMU_WASM_DIR) || { echo "ERROR: $(QEMU_WASM_DIR) submodule missing; run 'git submodule update --init --recursive'" >&2; exit 1; }
    	@echo ">>> Building qemu-wasm via docker (~5-10 minutes on first run)..."
    	cd $(QEMU_WASM_DIR)/examples/riscv64 && ./build.sh
    	@mkdir -p $(QEMU_OUT_DIR)
    	@echo ">>> Copying artifacts to $(QEMU_OUT_DIR)..."
    	cp $(QEMU_WASM_DIR)/examples/riscv64/src/htdocs/out.js                         $(QEMU_OUT_DIR)/
    	cp $(QEMU_WASM_DIR)/examples/riscv64/src/htdocs/qemu-system-riscv64.wasm       $(QEMU_OUT_DIR)/
    	cp $(QEMU_WASM_DIR)/examples/riscv64/src/htdocs/qemu-system-riscv64.worker.js  $(QEMU_OUT_DIR)/
    	cp $(QEMU_WASM_DIR)/examples/riscv64/src/htdocs/qemu-system-riscv64.data       $(QEMU_OUT_DIR)/
    	cp $(QEMU_WASM_DIR)/examples/riscv64/src/htdocs/load.js                        $(QEMU_OUT_DIR)/
    	@echo ">>> Done. Remember to 'git add $(QEMU_OUT_DIR)' and commit."

    clean-qemu-assets:
    	rm -f $(QEMU_OUT_DIR)/out.js $(QEMU_OUT_DIR)/qemu-system-riscv64.* $(QEMU_OUT_DIR)/load.js
    ```

    // QEMU argv for the bootroom Phase 1 walking skeleton.
    // Derived from qemu-wasm/examples/riscv64/src/htdocs/module.js with the

    //! Build script for the bootroom binary.
    //!
    //! Phase 1: validates that the qemu-wasm artifacts (built once via
    //! `make qemu-assets` and committed to git per CONTEXT.md D-02) are
    //! present. Does NOT invoke docker — that would be Pitfall 9.

    use std::path::Path;

    const REQUIRED: &[&str] = &[
        "assets/qemu/qemu-system-riscv64.wasm",
        "assets/qemu/qemu-system-riscv64.worker.js",
        "assets/qemu/qemu-system-riscv64.data",
        "assets/qemu/out.js",
        "assets/qemu/load.js",
        "assets/qemu/module.js",
    ];

    fn main() {
        println!("cargo:rerun-if-changed=assets/qemu");

        for rel in REQUIRED {
            let p = Path::new(rel);
            if !p.exists() {
                // cargo::error= is the supported way to emit a build-script
                // error that cargo formats cleanly.
                println!(
                    "cargo::error=qemu-wasm assets missing. Run 'make qemu-assets' from the repo root. (missing: {})",
                    rel
                );
                std::process::exit(1);
            }
        }
    }
    ```

    The exit-1 + cargo::error directive is the supported pattern for build-script failure since Cargo 1.84. Note: emit `cargo::error=` (double-colon — current Cargo syntax) rather than the legacy `cargo:warning=`. If the executor finds the host cargo only supports the single-colon legacy syntax, fall back to writing to stderr + non-zero exit; the failure mode is the same.

    Then run `cargo build --workspace` and confirm it still succeeds (because Task 1 left the artifacts in place). Then for verification: temporarily rename `crates/bootroom/assets/qemu/qemu-system-riscv64.wasm`, re-run `cargo build`, confirm the friendly error appears, then restore the file.

    ```markdown
    # Rebuilding the qemu-wasm artifacts

    The files in this directory are produced by the qemu-wasm submodule's docker
    build. They are committed to git so end users do NOT need docker installed
    to `cargo build` bootroom. Per CONTEXT.md decision D-02.

    ## When to rebuild

    - You bumped the `qemu-wasm` submodule pinned commit in `.gitmodules`.
    - Upstream qemu-wasm fixed a bug you want.
    - You changed the QEMU argv in `module.js` and want to verify boot.

    ## Prerequisites

    - `docker` 20.10+ (verified 2026-05-17 on docker 29.4.3).
    - `make` (GNU Make 4.x).
    - The `qemu-wasm` git submodule checked out: `git submodule update --init --recursive`.
    - Free disk: ~5 GB for the docker build context and intermediate layers.
    - Time: 5–15 minutes on first run; ~1 minute on warm builds.

    ## Procedure

    From the repo root:

        make qemu-assets

    This runs the qemu-wasm/examples/riscv64 docker build, then copies the
    output files into `crates/bootroom/assets/qemu/`. After it completes:

        git status crates/bootroom/assets/qemu/
        git add crates/bootroom/assets/qemu/
        git commit -m "build: bump qemu-wasm artifacts to <submodule-sha>"

    The submodule SHA is `git -C qemu-wasm rev-parse HEAD`.

    ## What ends up committed

    | File | Approx size | What it is |
    |------|-------------|------------|
    | `qemu-system-riscv64.wasm`     | 10–30 MB | The QEMU RISC-V system emulator compiled to WebAssembly. |
    | `qemu-system-riscv64.worker.js`| <100 KB  | Emscripten pthread worker shim. |
    | `qemu-system-riscv64.data`     | 5–20 MB  | Emscripten preload pack containing the `/pack/` filesystem with the `Image` slot. |
    | `out.js`                       | 100–500 KB | Emscripten JS glue + `initEmscriptenModule` default export. |
    | `load.js`                      | <5 KB    | Classic script that primes the page before the module loads. |
    | `module.js`                    | <2 KB    | bootroom-authored QEMU argv (NOT generated; do not overwrite via `make qemu-assets`). |

    ## Special handling: `module.js`

    `module.js` is bootroom-authored, not produced by the docker build. The
    Makefile copies the other five files; `module.js` stays put. If you need
    to change the QEMU argv (e.g., add a `-drive` for a rootfs), edit
    `module.js` directly and commit.

    ## Validation

    After commit, sanity check on a clean checkout:

        cargo clean
        cargo build --workspace

    If you forgot to commit any file, `build.rs` will tell you which one with
    a friendly error.

    ## What NOT to do

    - Do not run docker from `build.rs`. (Pitfall 9.)
    - Do not check in any docker intermediate state.
    - Do not switch this directory to Git LFS without team consensus —
      `cargo install bootroom` users would need git-lfs installed.
    - Do not compress the wasm file. The browser caches it; the binary
      compresses fine at the OS layer.
    ```

    Keep it terse, no marketing voice.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| qemu-wasm submodule → committed artifacts | The committed bytes ARE the trust anchor — once committed, future `cargo build` invocations trust them implicitly. |
| docker build → maintainer machine | The docker build runs upstream code; trust assumption is "we trust the qemu-wasm pinned commit". |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02-01 | Tampering (supply chain) | qemu-wasm submodule pin | mitigate | Submodule pin in `.gitmodules` lock the SHA; REBUILD.md tells maintainer to commit with the SHA in the message. |
| T-01-02-02 | Tampering (artifact substitution) | Committed wasm/data files | accept | Git history is the integrity log; reviewers spot suspicious binary diffs at PR time (`.gitattributes` marks them binary so diffs aren't text-mangled). |
| T-01-02-03 | Denial of Service | Build environment requires docker | mitigate | Maintainer-only requirement; users build from committed artifacts (no docker dep). Makefile fails-fast with a clear message if docker is absent. |
| T-01-02-04 | Information Disclosure | Build-host path leakage via include_dir | accept | Tracked as open question A.4 in 01-RESEARCH.md; verified in plan 01-07 via `strings target/release/bootroom | grep -F '$HOME'`. Not Phase 1 blocking. |
</threat_model>
