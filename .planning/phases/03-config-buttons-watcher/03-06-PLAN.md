<objective>
Build the watcher subsystem: one `notify-debouncer-full` instance, two watches (`bootroom.toml` + kernel parent dir), demux by canonical path, size-stability + ELF magic gates for the kernel path, broadcast WS messages to all subscribers.

Purpose: WCH-01..05 are entirely about the watcher's correctness; CFG-10 is the TOML-side hook. Pitfall #4 (size-stability) and Pitfall #2 (callback thread is NOT a tokio runtime) are the load-bearing traps RESEARCH calls out repeatedly. This plan is the heaviest in the phase (Wave 3, single plan owning 6 of 19 reqs).

Output: A new `watcher.rs` module + 6 integration test files covering each watcher requirement. The debouncer is constructed in `server::run` after AppState exists, leaked via `Box::leak` (process lifetime — bootroom has no graceful shutdown). The JSON projection helper `project_loaded_to_json` lives here and is RE-USED by Plan 07's `/api/config` handler (Plan 07 imports it).

  <behavior>
    - `spawn_watcher(state)`:
      - Computes `kernel_parent = state.kernel_canon.parent().ok_or(...)`, `kernel_basename = state.kernel_canon.file_name().ok_or(...)`.
      - Constructs the debouncer per RESEARCH Pattern 1 (300ms window, sync callback).
      - The callback receives `DebounceEventResult`; iterates `Ok(events)` looking at `ev.event.paths.last().unwrap_or(first)` (rename pairs put dst last), demuxes config vs kernel:
          - If `target == &state.config_path_canon` → set `config_dirty = true`.
          - Else if `target.parent() == Some(&kernel_parent) && target.file_name() == Some(&kernel_basename)` AND `EventKind` is Modify/Create/Remove → set `kernel_dirty = true`.
          - Other events ignored.
      - After loop: if `config_dirty` → `handle_config_change(&state, &state.ws_broadcast)`; if `kernel_dirty` → `handle_kernel_change(&state, &state.ws_broadcast)`. Both are sync; broadcast::Sender::send is sync.
      - `Box::leak(Box::new(debouncer))` to keep the OS thread alive for process lifetime.
    - `handle_kernel_change(state, tx)` per RESEARCH Pitfall #4:
      - Read `s1 = std::fs::metadata(&state.kernel_canon).ok().map(|m| m.len())`. If `None` (file gone) return (next event will retry).
      - `std::thread::sleep(Duration::from_millis(100))` — SYNC sleep inside the OS-thread callback, NOT a tokio sleep.
      - Read `s2`. If `s1 != s2` → `tracing::debug!("kernel size unstable {s1:?} -> {s2:?}; deferring")` and return (next debounce tick retries).
      - Read first 4 bytes via `std::fs::File::open + read_exact`. Compare to `[0x7f, b'E', b'L', b'F']`.
      - If non-ELF → `let _ = tx.send(WsMessage::KernelChanged { ok: false, mtime: 0, size: s1.unwrap_or(0), sha256_prefix: String::new(), reason: Some("not ELF".into()) });` and return. The `let _ =` swallows `SendError` per Pitfall #3 (no subscribers is acceptable).
      - If ELF: compute mtime via `metadata.modified().and_then(|t| t.duration_since(UNIX_EPOCH))` → seconds as i64. Compute sha256_prefix via `sha2::Sha256::new() + std::fs::read(&state.kernel_canon)` then `hex::encode(&digest[..6])` (12 hex chars). Reuse the same algorithm `kernel_info.rs` already uses. Broadcast `KernelChanged { ok: true, mtime, size, sha256_prefix, reason: None }`. Note: this duplicates the hashing path with `/api/kernel/info`'s digest cache; per RESEARCH the watcher does NOT write to the digest_cache (avoid two writers of the same state) — accept the duplicate hash cost (kernel reads are infrequent).
      - On any I/O error during the hash, broadcast `KernelChanged { ok: false, mtime: 0, size: s1.unwrap_or(0), sha256_prefix: String::new(), reason: Some(format!("hash error: {e}")) }` and return. Resilient to mid-build races.
    - `handle_config_change(state, tx)`:
      - Read `bytes = std::fs::read_to_string(&state.config_path_canon)`. On Err → broadcast `ConfigInvalid { error: format!("{e}"), line: None, col: None }` and return. This handles the chmod-a-r case (Open Question #3 in RESEARCH).
      - `LoadedConfig::load_from_str(&bytes)`:
          - Err(e) → broadcast `ConfigInvalid { error: e.message, line: e.line, col: e.col }`. Do NOT mutate `state.loaded_config`.
          - Ok(loaded) → swap into the lock: enter a tokio runtime handle to do the async write, OR use the blocking variant: `state.loaded_config.blocking_write()` (which works because the callback is on a non-tokio thread; calling `.blocking_write()` from inside a tokio runtime would panic, but we explicitly are NOT in one here). Use `blocking_write`. Then project the new config via `project_loaded_to_json(&loaded)` and broadcast `ConfigUpdate { config: <Value> }`.

    - In `server::run`: after `AppState::new(...)` and BEFORE `let app = build_router(state);`, call `crate::watcher::spawn_watcher(state.clone())?;`. If it fails (canonicalization of parent dir or `.watch()` call), bail with context — operator gets a clear "watcher init failed" message.

    - Integration tests (6 new files; each spawns a fresh AppState using a TempDir for both kernel and config paths, gets a `broadcast::Receiver` via `state.ws_broadcast.subscribe()`, runs `spawn_watcher`, performs a filesystem mutation, and asserts the expected WS frame appears on the receiver within a generous timeout — 2 seconds):

        3. **`tests/watcher_size_stability.rs::partial_write_held_until_stable`** (WCH-03): write 32 bytes (size 32, ELF magic), wait 50ms, write 32 more bytes (size 64), wait 50ms; the FIRST debounce tick should see size jumping 32→64 across the 100ms inner check → deferred; the SECOND debounce tick after settling should fire one `KernelChanged`. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Filesystem events → notify-debouncer-full → callback OS thread | Any process on the system that can write to the kernel parent dir or bootroom.toml triggers events. |
| OS thread → broadcast::Sender → tokio WS subscribers | Cross-thread message passing; broadcast is the sanctioned primitive. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-06-01 | DoS (self-inflicted) | watcher event amplification | mitigate | 300ms debounce window collapses bursts (WCH-01 test asserts). Per-receiver broadcast cap 16 with Lagged-drops-oldest semantics; Plan 08 logs Lagged at warn (no log-amplification — `skipped` is a u64 count). |
| T-03-06-02 | Tampering (partial-write race) | handle_kernel_change | mitigate | Size-stability across 100ms inner check; ELF magic sniff; defer on instability. Tested in `partial_write_held_until_stable`. |
| T-03-06-03 | Tampering (non-ELF accepted) | ELF magic check | mitigate | First 4 bytes compared to `\x7f ELF`; non-ELF broadcasts `ok: false` warning frame, never `ok: true`. Tested in `non_elf_yields_ok_false`. |
| T-03-06-04 | Confused deputy (silent watcher death) | Box::leak(debouncer) | accept | RESEARCH Pitfall #7 explicit: dev-tool, recovery is restart. Log loudly in callback `Err(errs)` branch. Post-MVP refactor (out of scope) stores Debouncer in AppState with a watchdog. |
| T-03-06-05 | Tampering (config bypass) | Lagged ConfigUpdate | mitigate | Per RESEARCH Pitfall #3 + `<specifics>`: full replacement on every update; a dropped frame is recovered by the NEXT update. Plan 08 logs Lagged. |
| T-03-06-06 | Tampering (atomic-save race) | TOML reload during partial write | accept | partial-file reads may fail to parse → broadcasts `ConfigInvalid` (transient; next save fires another event). Documented in CONTEXT `<specifics>`. |
| T-03-06-07 | DoS (memory) | reading the entire kernel file for sha256 | accept | Kernel is the file the operator chose to load into qemu-wasm; they already accepted its size. Phase 2 `/api/kernel/info` makes the same trade. Duplicate hashing here keeps digest_cache as a single-writer path. |
| T-03-06-08 | Information disclosure | ConfigInvalid error text | accept | Echoes operator's own TOML message; no secret surface. |
</threat_model>
