<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| WsMessage::ConfigInvalid.error → DOM | Server-supplied string (originally from `toml` crate's parse error, which echoes operator's own TOML field names) — must NEVER be inserted via innerHTML. |
| WsMessage::KernelChanged.reason → DOM | Server-supplied string ("not ELF", or `format!("hash error: {e}")` from Plan 06) — same textContent-only rule. |
| Action's bytes_b64 → funnel.enqueue | Server-encoded base64 from /api/config; the only path to inject bytes into the guest serial; lock-aware at the caller. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-11-01 | Tampering (XSS into banner) | renderConfigBanner | mitigate | Use textContent for both the strong and .err-body inserts. Grep gate in `<verify>` pins innerHTML count at 2 (unchanged from Phase-1+2 baseline). Reviewer-visible regression detection. |
| T-03-11-02 | Tampering (lock bypass) | xterm.onData / action-btn click guards | mitigate | Both call sites check `funnel.locked` BEFORE enqueue. The WS SerialIn branch is intentionally lock-agnostic per CONTEXT.md. Future caller-site additions (e.g., paste handlers, drag-drop) must respect the same guard — documented in app.js comment block at the top of the lock-aware section. |
| T-03-11-03 | DoS (re-render storm) | ConfigUpdate handler | mitigate | replaceChildren is O(n) synchronous; ConfigUpdate frames are debounced at 300ms by the watcher (Plan 06). Worst case ≈3-4 re-renders per second; xterm and DOM both handle this trivially. |
| T-03-11-04 | Confused deputy (banner priority bypass) | resolveBanners | mitigate | Single synchronous function runs after every state mutation. UI-SPEC ladder enforced by setting `hidden` on lower-priority banners; no race window because JS is single-threaded. |
| T-03-11-05 | Information disclosure | dismiss is per-event not persistent | accept | UI-SPEC line 362 explicit. No `localStorage`-backed preference; the simplicity is the feature. |
| T-03-11-06 | Tampering (CLI vs config bytes mismatch) | action-btn data-bytes-b64 | mitigate | bytes are base64-encoded server-side from `LoadedConfig::ResolvedAction.bytes_decoded` which is computed ONCE via `decode_bytes_escape` (Plan 01) and projected through `project_loaded_to_json` (Plan 06). The browser never re-decodes escape sequences — only b64ToBytes. Drift impossible by construction. |
| T-03-11-07 | DoS (slow lock observer) | _notifyLockObserver | mitigate | Plan 10 wrapped observer call in try/catch (mirrors WR-05). If the app.js observer throws (e.g., DOM not ready), the lock state change still completes. |
</threat_model>
