## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → check_cmd | `bootroom check` reads operator-pointed paths; arbitrary file contents enter the TOML parser. |
| init_cmd → CWD filesystem | `bootroom init` writes a single file in CWD; refuses overwrite without `--force`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04-01 | Tampering | check_cmd file read | accept | `--config` is operator-supplied; trusted-input per RESEARCH Security Domain. Any path the operator can type they can already `cat`. No `--config` traversal mitigation needed. |
| T-03-04-02 | Tampering (data) | init_cmd overwriting work | mitigate | Refuse overwrite without `--force`; verbatim error line. Tested in `init_refuses_overwrite_without_force` (asserts file content unchanged after refused init). |
| T-03-04-03 | DoS | check_cmd reading huge config | accept | `std::fs::read_to_string` allocates up to file size; operator chooses ceiling. `toml = "1.1"` is winnow-backed (finite memory per RESEARCH). Not a remote DoS surface. |
| T-03-04-04 | Information disclosure | check_cmd stderr error contents | accept | Echoes back the operator's own file path and `LoadError::message` (their own typo). No secret leakage path. |
</threat_model>
