<objective>
Extend `AppState` with the four new pieces of state Plans 06, 07, 08 will consume: a canonical config path, a canonical kernel path, an Arc<RwLock<LoadedConfig>> for in-flight reloads, and a broadcast::Sender<WsMessage> for fan-out to WS subscribers.

Purpose: Centralize state ownership BEFORE the watcher (Plan 06), `/api/config` (Plan 07), and the WS broadcast forwarder (Plan 08) are wired. Without canonicalization at startup the watcher will silently miss its own config edits (Pitfall #1). Without a broadcast channel constructed in AppState there's no shared identity between the watcher thread and the WS handler.

Output: `AppState` carries five new fields (config_path, config_path_canon, kernel_path_canon, loaded_config, ws_broadcast). `server::run` loads + validates the config at startup and bails before binding the listener if it's invalid. All existing Phase-2 tests still pass via an updated `tests/common/mod.rs::spawn` helper.
</objective>
