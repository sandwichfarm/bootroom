<interfaces>
The cargo-deny config schema is documented at https://embarkstudios.github.io/cargo-deny/checks/index.html.

Four cargo-deny check categories:
- licenses: SPDX-expression based license enforcement
- advisories: RustSec advisory DB matches
- bans: ban specific crates or duplicates
- sources: restrict crate sources (crates.io vs git deps)

Rust-ecosystem permissive licenses commonly present in dep trees:
- MIT, Apache-2.0 (the main two)
- Apache-2.0 WITH LLVM-exception (compiler-stack deps)
- BSD-2-Clause, BSD-3-Clause (BSD-licensed crates)
- ISC (smaller utility crates)
- Unicode-DFS-2016 (unicode-ident, used by syn)
- Unicode-3.0 (newer unicode crates)
- Zlib (some compression libs)
- MPL-2.0 (weak copyleft; debatable; default to NOT allowing to force explicit decision)

Pin cargo-deny v0.14+ to match the documented schema.
</interfaces>

  <action>Create `deny.toml` at the workspace root with the structure below. Use the cargo-deny v0.14+ schema.

The file contains four top-level tables: `[graph]`, `[licenses]`, `[bans]`, `[advisories]`, `[sources]` (and a small `[output]` block).

`[graph]` block:
- `all-features = true` — checks all features to catch platform-specific license differences.

`[output]` block:
- `feature-depth = 1` — keeps inclusion-graph output readable.

`[licenses]` block — the heart of D-10. Required keys:
- `unlicensed = "deny"` — anything not on the allow-list below requires explicit triage.
- `confidence-threshold = 0.93` — cargo-deny's recommended value for ambiguous license-text matching.
- `allow = [...]` — explicit SPDX-expression allow-list. Include:
  - `"MIT"` (our own + most Rust crates)
  - `"Apache-2.0"` (our own + most Rust crates)
  - `"Apache-2.0 WITH LLVM-exception"` (compiler-stack crates like rustix)
  - `"BSD-2-Clause"`, `"BSD-3-Clause"` (older BSD-licensed deps)
  - `"ISC"` (tiny utility crates like ring, untrusted)
  - `"Unicode-DFS-2016"` (unicode-ident, transitive through syn / serde-derive)
  - `"Unicode-3.0"` (newer unicode crates)
  - `"Zlib"` (some compression / bindings)
  - `"CC0-1.0"` (public-domain-equivalent)
  - `"BSL-1.0"` (Boost Software License)
  - `"MPL-2.0"` (weak copyleft; with a comment naming the rationale — webpki-roots and similar deps use it; allowed because they don't impose source-disclosure on bootroom's binary; re-evaluate if MPL-2.0 deps proliferate)
- `deny = [...]` — explicit deny list for belt-and-suspenders defense. Include: `"GPL-2.0"`, `"GPL-3.0"`, `"AGPL-3.0"`, `"LGPL-2.1"`, `"LGPL-3.0"`, `"SSPL-1.0"`.
- `exceptions = []` (empty by default; per-crate license exceptions go here with rationale).
- `clarify = []` (empty by default; for crates with missing-but-known license metadata).

`[bans]` block:
- `multiple-versions = "warn"` — warn-only (workspace pins major versions; duplicates are mostly cosmetic).
- `wildcards = "deny"` — no `*` version specifiers (none should exist; workspace deps are all pinned).
- `deny = []` (empty).

`[advisories]` block:
- `yanked = "warn"` — start permissive to avoid first-run CI failure on pre-existing findings.
- `unmaintained = "all"` — surface all unmaintained warnings; cargo-deny treats this as warn-by-default.
- `unsound = "warn"` — start permissive; promote to `"deny"` once baseline is clean.
- `ignore = []` (empty by default; vetted ignores go here with rationale).

`[sources]` block:
- `unknown-registry = "deny"` — only allow registries on the explicit list.
- `unknown-git = "deny"` — no git deps allowed (none exist in `Cargo.toml`).
- `allow-registry = ["https://github.com/rust-lang/crates.io-index"]` — the canonical crates.io URL.
- `allow-git = []`.

Add a header comment at the top of the file explaining the file's purpose and how to run locally (`cargo deny check`). Add inline comments next to non-obvious allow-list entries (especially Unicode-DFS-2016 → "syn dep", MPL-2.0 → re-evaluation rationale).

Do NOT add a `[licenses.private]` block — workspace's own crates inherit the workspace license expression and don't need a private exception.

Do NOT include SPDX expressions for the project's own crates — `[licenses]` only applies to dependencies.</action>

2. **License finding:** A dep uses a license not on the allow-list (e.g. `Unlicense` or `OFL-1.1`). For each:

<task type="auto">
  <name>Task 3: Write `.github/workflows/ci-deny.yml`</name>
  <files>.github/workflows/ci-deny.yml</files>
  <action>Create `.github/workflows/ci-deny.yml` — a small workflow that runs `cargo deny check` on every push and PR to master. This is separate from the cargo-dist release.yml (which only runs on `v*` tags) and from any future general CI workflow (which doesn't exist yet).

File contents (verbatim):

```yaml
name: cargo-deny

on:
  push:
    branches: [master]
  pull_request:
    branches: [master]

# cargo-deny is a license/security gate; cancel superseded runs.
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  cargo-deny:
    name: cargo deny check
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      # Pin the cargo-deny version explicitly. Drift between local and CI is
      # impossible if this version matches the one used in 06-05 Task 2.
      # Bump in lockstep with the local install. Currently pinned to v0.14.x
      # (cargo-deny's v0.14+ schema is what deny.toml is written against).
      - name: Install cargo-deny
        run: cargo install cargo-deny --locked --version ^0.14

      # `--hide-inclusion-graph` keeps log output bounded; full graph still
      # appears in the rendered failure output when an issue is found.
      - name: Run cargo deny check
        run: cargo deny check --hide-inclusion-graph
```

Notes:

- `on:` triggers cover both push-to-master (post-merge regression catch) and PR (pre-merge gate). The branch name `master` matches the existing repo (verified via `git status`).
- `concurrency` block cancels superseded runs on the same branch/PR — saves runner minutes when force-pushing.
- `runs-on: ubuntu-latest` — cargo-deny has no OS-specific behavior; ubuntu is the cheapest runner.
- `cargo install cargo-deny --locked --version ^0.14` pins the major-minor; the exact version used locally is captured in 06-05 Task 2's SUMMARY. The `^0.14` carets allow patch upgrades without a manual workflow edit. If a v0.15 lands with a breaking schema change, this workflow refuses the upgrade and a maintainer must explicitly bump.
- `cargo deny check` without subcommand args runs all four checks (licenses, advisories, bans, sources).
- `--hide-inclusion-graph` keeps the success-case log tiny. cargo-deny's failure-mode output ignores this flag (it always shows the graph when an issue is found).
- Do NOT add `continue-on-error: true` anywhere — this is a hard gate.
- Do NOT add a separate matrix or job for "check on multiple cargo-deny versions" — pin to one version and bump deliberately.
- Do NOT add a `cargo build` or `cargo test` step here — this workflow is purely cargo-deny. General CI (build/test) is out of scope for Phase 6 (no requirement covers it).</action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| crates.io dep tree → bootroom binary | Every transitive dep contributes license metadata. cargo-deny verifies license expressions are on the explicit allow-list before the workspace can build in CI. |
| `deny.toml` allow-list → published binary's effective license | The allow-list IS the project's compatibility statement. Any expansion is a legal-posture change that requires explicit review. |
| Push to master / PR open → CI cargo-deny run | The cargo-deny workflow runs on every push and PR. Forks running CI on their own PRs see the same gate. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-06-05-01 | Tampering | Contributor adds a GPL-3.0 dep | mitigate | `[licenses].allow` does not include GPL-3.0; explicit `[licenses].deny` also rejects it. CI fails on the first build. |
| T-06-05-02 | Tampering | Contributor edits deny.toml to relax the allow-list | mitigate | All changes to deny.toml are visible in git diff; standard code-review hygiene catches malicious or sloppy edits. The allow-list comments name the first introducer for each license, which makes review tractable. |
| T-06-05-03 | Spoofing | A dep declares a permissive license but actually contains restrictive code | accept | Outside cargo-deny's verification model. cargo-deny relies on the SPDX expression in the dep's manifest; verifying the actual license text against the declared expression is an independent audit (cargo-deny has a `confidence-threshold` but it operates on the LICENSE file text). 0.93 threshold is the project default. |
| T-06-05-04 | Repudiation | cargo-deny version drift between local dev and CI causes inconsistent gate behavior | mitigate | Task 2 and Task 3 pin cargo-deny to `^0.14`. Local installs use `--locked`; CI uses `--locked --version ^0.14`. Drift impossible within 0.14.x. |
| T-06-05-05 | Information Disclosure | deny.toml leaks sensitive info | accept | No secret material in the config; everything is policy. Publicly committed by design. |
| T-06-05-06 | Denial of Service | RustSec advisory database is unreachable | accept | `cargo deny check advisories` would error out. Operational concern; advisories block is `warn`-mode anyway, so a DB outage doesn't fail CI in a blocking way at this configuration. |
| T-06-05-07 | Elevation of Privilege | A new dep transitively pulls in a git-source dep | mitigate | `[sources].unknown-git = "deny"` rejects any git-source dep. cargo-deny fails the build before the dep can be linked. |
| T-06-05-08 | Tampering | A workspace-internal crate is mistakenly checked against the dep allow-list | accept | cargo-deny excludes workspace members from the licenses check by default. The lone path-dep (bootroom-core) is not checked against the allow-list. |
</threat_model>
