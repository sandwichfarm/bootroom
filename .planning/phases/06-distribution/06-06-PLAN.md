<objective>
Stand up `.github/workflows/release-smoke.yml`, a release-time gate that runs BEFORE the cargo-dist-generated release.yml publishes to crates.io. The gate's mechanics: spin up a clean Docker container (MSRV-1.85 image), `cargo install --locked` the just-built crate from a local tarball, and verify the installed binary works via `bootroom doctor --format json`. If the smoke fails, the publish never happens. This is CONTEXT.md D-05's "Docker-isolated `cargo install --locked` + `bootroom doctor` BEFORE the release tag triggers crates.io publish" verbatim.

Purpose: DIST-03 ("Published to crates.io; `cargo install bootroom` from a clean container produces a working binary") REQUIRES the gate. Without it, a regression in `[package].include` (06-02), a corrupted asset (Phase 1's qemu-wasm artifacts), or a missing build.rs dependency would only surface AFTER publish — and crates.io publishes are nearly irreversible (yanking is possible but not undo). DIST-05 ("Binary runs from any working directory") is additionally validated: the Docker container's CWD is `/` or `/root`, not the source dir, so `include_dir!` embedding is exercised path-independently. 06-08 layers on top of this with an explicit `/tmp`-CWD verification.

Output: A new release-smoke workflow + a tiny Rust integration test serving as the in-container smoke driver. The workflow is wired into cargo-dist's release.yml gating per the job names captured in 06-03 Task 3's SUMMARY.
</objective>

Why a Rust test instead of a shell script: consistency with the rest of the test suite (`crates/bootroom/tests/*.rs`), Cargo-managed dependency resolution (`serde_json` for JSON parsing is already a workspace dep), and `cargo test --test install_smoke -- --ignored` is a single, well-known invocation.

File contents:

```rust
//! Release-smoke install verification.
//!
//! This test is `#[ignore]` so it does not run as part of the normal
//! `cargo test` suite. The release-smoke GitHub Actions workflow
//! (.github/workflows/release-smoke.yml) runs it explicitly via
//! `cargo test --test install_smoke -- --ignored` AFTER `cargo install
//! --locked --path crates/bootroom` has placed the binary on PATH inside
//! a Docker container.
//!
//! Required state for this test to pass:
//! - `bootroom` binary on PATH (via cargo install during the smoke job).
//! - CWD is intentionally NOT the source tree — typically `/` or `/root`
//!   inside the Docker container. This exercises DIST-05's path-
//!   independence requirement (assets embedded via include_dir!).
//! - Optionally, `BOOTROOM_INSTALL_SMOKE_BIN` env var can override the
//!   binary path (for local debugging without rebuilding the container).

use std::process::Command;

fn bootroom_bin() -> String {
    std::env::var("BOOTROOM_INSTALL_SMOKE_BIN").unwrap_or_else(|_| "bootroom".to_string())
}

#[test]
#[ignore]
fn doctor_overall_is_pass_after_cargo_install() {
    let bin = bootroom_bin();

    // Run from CWD that is NOT the source tree. The release-smoke workflow
    // ensures this; locally, run from /tmp or pass --current-dir.
    let output = Command::new(&bin)
        .args(["doctor", "--format", "json"])
        .output()
        .unwrap_or_else(|e| panic!("failed to invoke `{} doctor`: {}", bin, e));

    assert!(
        output.status.success(),
        "bootroom doctor exited non-zero: stdout={:?} stderr={:?}",
        String::from_utf8_lossy(&output.stdout),
        String::from_utf8_lossy(&output.stderr),
    );

    let stdout = String::from_utf8(output.stdout)
        .expect("bootroom doctor stdout must be UTF-8");

    let parsed: serde_json::Value = serde_json::from_str(&stdout)
        .unwrap_or_else(|e| panic!("bootroom doctor --format json produced non-JSON: {}\nstdout:\n{}", e, stdout));

    let overall = parsed
        .get("overall")
        .and_then(|v| v.as_str())
        .expect("bootroom doctor JSON missing `overall` field");

    assert_eq!(
        overall, "pass",
        "bootroom doctor overall status was {:?}, expected \"pass\". Full JSON:\n{}",
        overall, stdout
    );
}

#[test]
#[ignore]
fn doctor_runs_from_tmp_cwd() {
    // DIST-05 path-independence check: change CWD to /tmp before invoking.
    // (06-08 expands this with explicit DIST-05 coverage; this is the
    // smaller in-test variant for the smoke gate's wave.)
    let bin = bootroom_bin();

    let output = Command::new(&bin)
        .args(["doctor", "--format", "json"])
        .current_dir("/tmp")
        .output()
        .unwrap_or_else(|e| panic!("failed to invoke `{} doctor` from /tmp: {}", bin, e));

    assert!(
        output.status.success(),
        "bootroom doctor exited non-zero when run from /tmp: stdout={:?} stderr={:?}",
        String::from_utf8_lossy(&output.stdout),
        String::from_utf8_lossy(&output.stderr),
    );
}
```

Notes:

- Both tests are `#[ignore]` so `cargo test --workspace` ignores them; only the release-smoke workflow runs them with `-- --ignored`.
- The first test is the DIST-03 gate proper (binary works after cargo install).
- The second test is a lightweight DIST-05 smoke; 06-08 layers a more thorough variant.
- `serde_json` is already a workspace dev-dep (and a regular dep for the bootroom crate); no Cargo.toml edit needed.
- Do NOT add `tokio` or async machinery — the test is synchronous `std::process::Command`.
- Do NOT add a `serve` smoke (running the HTTP server in the container). The smoke is `bootroom doctor` only; a full `serve` exercise would require qemu-wasm assets to be runnable in the container's Chromium, which is a much bigger test. `bootroom doctor` is the documented Phase 5 surface for "is the install healthy?" and is sufficient for the gate.
- Do NOT add `--config` or `--kernel` flags — `bootroom doctor` without args runs the default check set, which is what we want.

The file lives under `crates/bootroom/tests/` alongside the other integration tests; it's automatically picked up by `cargo test --test install_smoke`.</action>

  <action>Create `.github/workflows/release-smoke.yml`. This workflow triggers on `v*` tag push (same trigger as cargo-dist's release.yml) but runs the install smoke INSIDE a Docker container and exits non-zero if the smoke fails. cargo-dist's release.yml's publish step depends on this workflow via a `needs:` reference (added in Task 3).

File contents:

```yaml
name: release-smoke

on:
  push:
    tags:
      - 'v*.*.*'

jobs:
  smoke:
    name: cargo install + bootroom doctor (Docker)
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v4
        with:
          # Submodules contain qemu-wasm sources, but the qemu-wasm assets
          # are committed in-tree (crates/bootroom/assets/qemu/). Submodule
          # checkout is therefore NOT needed for the smoke — it would only
          # slow the workflow. If a future regression of the assets-are-
          # committed pattern lands, this needs to flip to `submodules: true`.
          submodules: false

      # Pack the bootroom crate locally. This produces a .crate tarball that
      # mirrors what would be published to crates.io. The smoke runs
      # `cargo install --locked --path .` against the unpacked tarball
      # contents inside the Docker container, simulating the publish-then-
      # install round trip without actually touching crates.io.
      - name: cargo package bootroom
        run: |
          cargo package -p bootroom-core --allow-dirty --no-verify
          cargo package -p bootroom --allow-dirty --no-verify
          ls -la target/package/

      # Run the install + doctor smoke inside a clean rust:1.85 container.
      # Why alpine: matches MSRV exactly (rust:1.85-alpine is the smallest
      # image with the right toolchain). musl libc is also what the released
      # linux artifacts target, so a successful alpine install is the
      # closest local proxy to a release-artifact install.
      - name: Install + doctor smoke
        run: |
          docker run --rm \
            -v "$PWD:/workspace:ro" \
            -w /tmp \
            rust:1.85-alpine \
            sh -euxc '
              apk add --no-cache musl-dev gcc git
              # Unpack the bootroom crate tarball into /work and install from there.
              mkdir -p /work
              # Look up the actual tarball name (versions roll forward).
              tar -xzf /workspace/target/package/bootroom-*.crate -C /work
              # cargo install --locked --path picks up the unpacked source.
              cargo install --locked --path /work/bootroom-* --root /usr/local
              # Verify the binary works from /tmp (NOT the source dir).
              cd /tmp
              bootroom --version
              # The actual gate: doctor JSON must report overall=pass.
              JSON=$(bootroom doctor --format json)
              echo "doctor JSON: $JSON"
              echo "$JSON" | grep -Eq "\"overall\"[[:space:]]*:[[:space:]]*\"pass\""
            '

      # Optionally also run the install_smoke integration tests inside the
      # container, using the just-installed bootroom on PATH. This catches
      # regressions the inline shell-script smoke doesn't.
      - name: Install + integration test smoke
        run: |
          docker run --rm \
            -v "$PWD:/workspace:ro" \
            -w /tmp \
            rust:1.85-alpine \
            sh -euxc '
              apk add --no-cache musl-dev gcc git
              mkdir -p /work
              tar -xzf /workspace/target/package/bootroom-*.crate -C /work
              cargo install --locked --path /work/bootroom-* --root /usr/local
              cd /workspace
              # Run the ignored install_smoke tests. The tests look up the
              # binary via BOOTROOM_INSTALL_SMOKE_BIN env var.
              BOOTROOM_INSTALL_SMOKE_BIN=/usr/local/bin/bootroom \
                cargo test --test install_smoke -p bootroom -- --ignored --nocapture
            '
```

Notes:

- Trigger pattern `v*.*.*` matches cargo-dist's default (confirm from 06-03 SUMMARY's captured pattern; if it differs, match it exactly so the two workflows fire on the same tag pushes).
- `submodules: false` because qemu-wasm assets are committed in-tree under `crates/bootroom/assets/qemu/` (Phase 1 decision); the submodule is only needed for `make qemu-assets` rebuilds, not for the smoke.
- The Docker image is `rust:1.85-alpine` — matches MSRV exactly and uses musl libc (the same C library the four linux release targets use). `apk add musl-dev gcc git` installs the build deps cargo needs.
- `-v "$PWD:/workspace:ro"` mounts the workspace read-only so the container can untar the crate tarball but cannot scribble back into the host. Read-only mount is the safer default.
- `-w /tmp` sets the container CWD to `/tmp`, NOT the source tree — this is the DIST-05 path-independence check.
- The first smoke is a shell-script-driven `bootroom doctor` JSON parse. The second is the Rust integration test. Both must pass.
- `--root /usr/local` puts the installed binary on PATH at `/usr/local/bin/bootroom`. Default would be `~/.cargo/bin/`, which would also work but `/usr/local` is more standard for "system" binaries inside containers.
- `bootroom --version` exercise is a sanity-check that the binary even launches before the deeper doctor probe.
- `timeout-minutes: 30` is generous; the actual run should be 5-10 minutes (Docker pull + apk add + cargo install + tests).
- Do NOT add `submodules: recursive` — the submodule has its own bulk; not needed for the smoke.
- Do NOT add `cargo build --release` here — the smoke uses the source-installed binary (which `cargo install` builds in release mode by default). Re-building separately would be wasted runner time.

Do NOT add a `release.yml` `needs:` reference in this task — Task 3 handles the cross-workflow gating mechanism.</action>

## Trust Boundaries

|---|---|
| Git tag push → release.yml + release-smoke.yml | Both workflows fire on the same `v*` tag. release-smoke must complete (green) before release.yml's publish job can proceed. |

| crates.io publish credentials | Held by `release.yml` only; `release-smoke.yml` has no access to publish credentials (no need; smoke does NOT publish). |
