<objective>
Add the DIST-05 verification layer. 06-02's `[package].include` allow-list mechanically enforces what goes IN the tarball; this plan mechanically verifies the assets are REACHABLE at runtime from a CWD that has no source-tree context. The smoke runs inside 06-06's Docker container, invokes the installed binary from `/tmp`, and asserts `bootroom doctor` reports a non-empty `qemu_wasm_rev` value — which can only happen if the embedded asset bundle actually shipped through cargo's package → install round trip.

Purpose: DIST-05 ("Binary runs from any working directory, no in-repo assumptions; assets embedded via `include_dir!`") is the most subtle Phase 6 requirement. A regression mode that 06-02's include-list audit doesn't catch: an asset CAN be in the tarball but unreachable at runtime if `include_dir!`'s path argument is wrong, if build.rs's REQUIRED check fires on tarball-build but the asset is then dropped from the resulting binary, or if a relative-path lookup in `bootroom doctor` accidentally reads from CWD instead of the embedded bundle. This plan's `/tmp`-CWD invocation kills all three regression modes.

Output: An extra `#[ignore]` test in `tests/install_smoke.rs` and an extra step in `release-smoke.yml`. No new files.
</objective>

```rust
//! Release-smoke install verification.
//!
//! [keep the existing module doc]

use std::process::Command;

fn bootroom_bin() -> String {
    std::env::var("BOOTROOM_INSTALL_SMOKE_BIN").unwrap_or_else(|_| "bootroom".to_string())
}

fn run_doctor_json_from(cwd: &str) -> serde_json::Value {
    let bin = bootroom_bin();
    let output = Command::new(&bin)
        .args(["doctor", "--format", "json"])
        .current_dir(cwd)
        .output()
        .unwrap_or_else(|e| panic!("failed to invoke `{} doctor` from {}: {}", bin, cwd, e));
    assert!(
        output.status.success(),
        "bootroom doctor exited non-zero (CWD={cwd}): stdout={:?} stderr={:?}",
        String::from_utf8_lossy(&output.stdout),
        String::from_utf8_lossy(&output.stderr),
    );
    let stdout = String::from_utf8(output.stdout)
        .expect("bootroom doctor stdout must be UTF-8");
    serde_json::from_str(&stdout)
        .unwrap_or_else(|e| panic!("bootroom doctor --format json produced non-JSON: {}\nstdout:\n{}", e, stdout))
}

#[test]
#[ignore]
fn doctor_overall_is_pass_after_cargo_install() {
    // Default CWD; mostly proves the binary launches at all.
    let parsed = run_doctor_json_from(".");
    let overall = parsed.get("overall").and_then(|v| v.as_str()).expect("overall field missing");
    assert_eq!(overall, "pass", "doctor JSON: {}", parsed);
}

#[test]
#[ignore]
fn doctor_runs_from_tmp_cwd() {
    // DIST-05 path-independence (basic): binary launches and reports pass
    // even when invoked from /tmp.
    let parsed = run_doctor_json_from("/tmp");
    let overall = parsed.get("overall").and_then(|v| v.as_str()).expect("overall field missing");
    assert_eq!(overall, "pass", "doctor from /tmp returned non-pass overall: {}", parsed);
}

#[test]
#[ignore]
fn path_independence_qemu_wasm_rev_present() {
    // DIST-05 strict check: the qemu-wasm-rev embedded file must be reachable
    // when CWD is /tmp. A regression in `[package].include` (06-02) or in
    // include_dir!'s path argument would manifest as an empty/missing
    // qemu_wasm_rev value here, failing this test before the publish job
    // (release-smoke gating).
    let parsed = run_doctor_json_from("/tmp");

    // Locate the qemu_wasm_rev entry in the checks array.
    let checks = parsed.get("checks")
        .and_then(|v| v.as_array())
        .expect("checks field missing or not an array");

    let rev_check = checks.iter()
        .find(|c| c.get("name").and_then(|n| n.as_str()) == Some("qemu_wasm_rev"))
        .expect("doctor JSON has no `qemu_wasm_rev` check entry");

    let rev_status = rev_check.get("status")
        .and_then(|s| s.as_str())
        .expect("qemu_wasm_rev check has no status");

    assert_eq!(
        rev_status, "pass",
        "qemu_wasm_rev status was {:?}, expected \"pass\". A non-pass status here usually means the qemu-wasm-rev.txt file is missing from the published crate (regression of 06-02's [package].include allow-list).\nFull JSON: {}",
        rev_status, parsed
    );

    // Also confirm the top-level qemu_wasm_rev field (if doctor exposes it
    // separately from the checks array) is non-empty.
    if let Some(rev) = parsed.get("qemu_wasm_rev").and_then(|v| v.as_str()) {
        assert!(!rev.is_empty(), "qemu_wasm_rev top-level field is empty: {}", parsed);
        assert_ne!(rev, "unknown", "qemu_wasm_rev is the documented degraded value 'unknown', meaning the embedded asset bundle did not ship: {}", parsed);
    }
}
```

Implementation notes:

1. Factor the JSON-parsing + invocation into a helper `run_doctor_json_from(cwd: &str)`. This avoids duplication across the three tests.

2. The new test (`path_independence_qemu_wasm_rev_present`) is the DIST-05 sentinel. It is intentionally strict: status must be exactly `"pass"`, not `"info"` or anything fuzzy. The Phase 5 spec is clear that qemu-wasm-rev being readable IS the pass condition.

3. The top-level `qemu_wasm_rev` field check is wrapped in `if let Some(...)` because Phase 5's exact JSON shape may put the value ONLY in the checks array, or also at the top level. The test accepts both — it asserts on the top-level value only if present.

4. Remove (or simplify) the existing `doctor_runs_from_tmp_cwd` test if it duplicates the new test — but the cleanest approach is to keep both: one does the cheap exit-status + overall=pass check; one does the deep qemu-wasm-rev check.

5. The "expected_unknown_means_assets_missing" comment in the assertion message is critical operator guidance. When a future engineer sees this test fail, the failure message should point them at 06-02 and the include allow-list, not at the doctor command itself.

6. Do NOT add a `path_independence_kernel_loads` test that tries to load a kernel from `/tmp` — that would require qemu-wasm to actually run, which is the Phase 4 / Phase 1 spike-B territory. DIST-05 only requires the binary RUNS from any CWD; the qemu-wasm-rev probe is the right surface for that check.

7. Do NOT add a `cwd != source dir` parametrized test — the `/tmp` invocation is sufficient. Adding more CWDs (`/`, `/var`, `/root`) provides no additional signal.

8. The file is automatically picked up by `cargo test --test install_smoke -- --ignored` — no Cargo.toml or workflow change required just for the new test (the existing `--ignored` flag picks up all three).</action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Published tarball → installed binary embedded assets | `include_dir!` walks the source tree at compile time. A missing file in the tarball causes a compile-time `build.rs` failure (REQUIRED check) — usually. But include_dir!'s exact resolution rules can edge-case past the REQUIRED check if the file is in `assets/qemu/` but cargo's include allow-list excludes it from the tarball: then a release build in the consumer environment fails because the asset isn't there. This test catches that exact failure mode. |
| Installed binary CWD → embedded asset lookup | `include_dir!` reads from the compiled-in bundle, NOT from CWD. The test forces CWD=/tmp to prove no accidental CWD-relative lookup leaked into the doctor command path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-06-08-01 | Tampering | A future code change makes `bootroom doctor`'s qemu-wasm-rev lookup CWD-relative | mitigate | This test runs from `/tmp`; a CWD-relative lookup would return empty or error. The test asserts non-empty, non-"unknown" value. |
| T-06-08-02 | Tampering | `[package].include` excludes qemu-wasm-rev.txt | mitigate | 06-02's allow-list explicitly includes the file (verified). This test is the runtime backstop: if the include list silently regresses, the smoke fails before publish. |
| T-06-08-03 | Tampering | qemu-wasm-rev.txt is in the tarball but build.rs's `include_dir!` macro misses it | mitigate | build.rs's REQUIRED constant lists the file; the macro and the constant are kept in sync. This test asserts the runtime-reachability invariant from the OTHER end of the pipeline. |
| T-06-08-04 | Repudiation | An empty qemu-wasm-rev.txt (zero-byte file) passes all upstream checks but fails downstream usefulness | mitigate | The test asserts the value is non-empty AND not the documented degraded "unknown" sentinel.
