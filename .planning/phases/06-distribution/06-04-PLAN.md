3. Append the two new target recipes at the end of the file (after `clean-qemu-assets`):

   ```
   # DIST-02: single-command local install. Uses --locked so the workspace
   # Cargo.lock is honored exactly; mismatched transitive deps would otherwise
   # break reproducibility for kernel-CI consumers. Installs to ~/.cargo/bin
   # by default (or whatever CARGO_INSTALL_ROOT points at).
   install:
   	cargo install --locked --path crates/bootroom

   # Local cross-platform release smoke. Runs cargo-dist's build pipeline against
   # the locked four targets; produces the same artifact set the GitHub Actions
   # release workflow (.github/workflows/release.yml) emits on a `v*` tag push.
   # Useful BEFORE pushing a tag to catch packaging regressions locally.
   #
   # Requires cargo-dist installed (`cargo install cargo-dist --locked`) and
   # cross-toolchains (cargo-zigbuild handles the linux musl cross; macOS hosts
   # may need additional setup for linux targets — see cargo-dist docs).
   #
   # This target does NOT publish to crates.io or to GitHub Releases — those
   # only happen via the on-tag CI workflow.
   release:
   	cargo dist build --artifacts=all
   ```

   Use tabs (not spaces) for recipe indentation — match the existing file's indentation style exactly. If the existing file uses tabs for recipes (as `make` requires), the new recipes do too.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| operator's shell → cargo install command | `make install` invokes `cargo install` with `--locked --path crates/bootroom`. The path is repo-relative; the lock file is the workspace's `Cargo.lock`. Both are trusted in-tree state. |
| operator's shell → cargo-dist build | `make release` invokes `cargo-dist`, which spawns `cargo-zigbuild` and downloads the zig toolchain on first run (cached afterwards). Cross-toolchain downloads are over HTTPS to canonical zig CDN. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-06-04-01 | Tampering | `--locked` flag missing → consumer gets non-reproducible install | mitigate | Task 1 explicitly bakes `--locked` into the recipe. Verification gate `grep -Fxq 'cargo install --locked --path ...'` enforces presence. |
| T-06-04-02 | Tampering | Path argument typo (e.g. `crates/bootroom/.` instead of `crates/bootroom`) | mitigate | Recipe is one literal line, verified by exact-match grep gate in Task 1. No expansion / no variable substitution. |
| T-06-04-03 | Denial of Service | `make release` fails because cargo-dist not installed | accept | `cargo dist build` produces a clear "command not found" or installer hint on first run. The `make release` block's leading comment documents the prerequisite (`cargo install cargo-dist --locked`). Operator-facing error; no mitigation needed beyond documentation. |
| T-06-04-04 | Denial of Service | `make release` fails because cross-toolchains aren't available on the host | accept | Same as T-06-04-03 — operator-facing error with a clear message from cargo-zigbuild. The leading comment block documents this caveat. |
| T-06-04-05 | Elevation of Privilege | `make install` writes outside `~/.cargo/bin/` | accept | `cargo install` always writes to `CARGO_INSTALL_ROOT` (defaulting to `~/.cargo/bin/`). No path traversal possible. Operator-controlled. |
| T-06-04-06 | Information Disclosure | `make release` artifacts contain unexpected files | mitigate (upstream) | The artifact set is determined entirely by 06-02's `[package].include` allow-list and 06-03's `[workspace.metadata.dist]` configuration. Any deviation is upstream of this plan. |
