<objective>
Pin both crates' publish surface with explicit `[package].include` allow-lists, and finish the publish-required metadata (`description`, `repository`, `homepage`, `keywords`, `categories`, `readme`, `documentation`). The allow-list closes Pitfall #4 from CONTEXT.md: `cargo publish` silently drops files that are either (a) not git-tracked OR (b) not in `include` if `include` is set. Without explicit `include`, the `.gitignore`-shadowed qemu-wasm artifacts (large binary `.wasm` / `.data` blobs in `assets/qemu/`) risk silent omission, breaking DIST-05 (embedded-asset path independence) at the worst possible time — only the post-publish smoke would catch it.

Purpose: DIST-05 (binary runs from any working directory because assets are embedded via `include_dir!`) is gated on the published tarball actually containing every asset `include_dir!` embeds. `[package].include` is the single mechanism that guarantees this. Also pins the surface so 06-03's cargo-dist can compute the workspace tarball deterministically.

Output: Both crate manifests with explicit `include = [...]` allow-lists covering exactly the files each crate needs, plus the publish-metadata fields crates.io expects to surface.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| repo workspace → crates.io tarball | `cargo publish` (driven by 06-03's release.yml) packages files per `[package].include`. Files outside the allow-list are silently dropped — this is the canonical Pitfall #4. |
| `include_dir!` macro → runtime asset loader | `include_dir!` reads from the crate's source tree at compile time. If the tarball is missing an asset, the next build of the published crate fails the `build.rs` REQUIRED check, and the failure mode is "the binary refuses to compile on the consumer's machine" — pre-runtime, but post-publish. |
| Workspace root files → per-crate tarball | LICENSE-MIT, LICENSE-APACHE, and README.md live at the workspace root, not inside the crate. Each crate's `include` references them with `../../` paths. Cargo resolves these and copies them into the tarball at their basenames. |
