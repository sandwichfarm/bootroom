<objective>
Capture `git rev-parse --short HEAD` into a compile-time env var `BOOTROOM_GIT_SHA` via `crates/bootroom/build.rs`, with a graceful `"unknown"` fallback for builds outside a git checkout (most notably `cargo install bootroom` from crates.io, which strips `.git/`). Wave-0 a tiny integration test that proves the env var is exposed end-to-end so 05-04 can `env!("BOOTROOM_GIT_SHA")` without surprise.

Purpose: The doctor `version` check reports `bootroom <CARGO_PKG_VERSION> (<sha>)` per CONTEXT.md D-DOC-04. The git SHA must be captured at build time because `cargo install` produces binaries with no `.git/` tree — a runtime `git rev-parse` would fail.

Output: Extended `build.rs` that emits one extra `cargo:rustc-env` directive and two `cargo:rerun-if-changed` directives. Wave-0 test scaffold under `crates/bootroom/tests/doctor_subcommand.rs` containing only the env-presence test (05-05 fills the rest).
</objective>

<!-- Pattern from research (Pattern 3): -->

build.rs main() extension shape:
```rust
// Append at end of fn main()
let sha = std::process::Command::new("git")
    .args(["rev-parse", "--short", "HEAD"])
    .output()
    .ok()
    .filter(|o| o.status.success())
    .and_then(|o| String::from_utf8(o.stdout).ok())
    .map(|s| s.trim().to_string())
    .filter(|s| !s.is_empty())
    .unwrap_or_else(|| "unknown".to_string());
println!("cargo:rustc-env=BOOTROOM_GIT_SHA={sha}");
println!("cargo:rerun-if-changed=.git/HEAD");
println!("cargo:rerun-if-changed=.git/refs");
```

Runtime consumer (lives in 05-04):
```rust
let sha = env!("BOOTROOM_GIT_SHA"); // ALWAYS defined because build.rs always emits it
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| build host → bootroom binary | Build-host git CLI output is captured into a compile-time string baked into the binary. Crosses from "build environment" trust domain to "shipped artifact" trust domain. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-05-01-01 | Tampering | `BOOTROOM_GIT_SHA` env emission | accept | Build host is already trusted (it produces the binary). A malicious build host can poison the SHA, but it can poison the entire binary anyway — no incremental risk. |
| T-05-01-02 | Denial of Service | build.rs `Command::new("git")` blocking | mitigate | `.ok()` on `Command::output()` swallows errors; no panic path. `output()` is synchronous but git rev-parse is sub-100ms; acceptable. |
| T-05-01-03 | Information Disclosure | Embedded SHA in shipped binary | accept | The SHA is intentionally public (it's used in `bootroom doctor` output for support requests). No secret material. |
| T-05-01-04 | Tampering | crates.io tarball lacks `.git/` → `unknown` SHA | mitigate (by design) | `"unknown"` is the documented degraded value. Operators inspecting `bootroom doctor` output for a `cargo install`-sourced binary see `unknown` and understand the build is unreproducible to a commit — this IS the security posture. |
</threat_model>
